# Оружейный верстак и модификации АК (0.3.0)

> **Статус проверки.** Код написан и проверен только статически (`tools/validate.py`, парсер `javac`, чтение кода).
> Он **не компилировался и не запускался в игре**; GameTest'ы `AkModsGameTests` тоже не запускались. Всё ниже описывает,
> как это *должно* работать по коду, а не результат игрового теста.

## Как пользоваться

1. Скрафтить **Оружейный верстак** (`GGG / PTP / I I`: стальная балка ×3, оружейные запчасти ×2, верстак, железо ×2).
2. ПКМ по верстаку — откроется окно. Положить **АК** в левый слот, **комплект** — в слот своего вида (слоты по порядку:
   магазин, механизм, стабилизатор, ствол, пружина; в слот не-своего вида предмет не кладётся; Shift+ЛКМ по предмету
   в инвентаре сам выбирает нужный слот).
3. Нажать **«Установить»**. Каждый комплект, которого ещё нет на этом автомате, записывается в автомат и **расходуется**.
   Комплект того вида, что уже стоит на автомате, не расходуется: он остаётся в слоте (слот краснеет, кнопка пишет
   «Уже установлено»).
4. Автомат можно забрать в любой момент: модификации лежат в самом автомате.

Окно показывает текущие характеристики автомата в слоте (магазин, перезарядка, скорострельность, разброс — зелёным
то, что улучшено модификацией), пять плашек «установлено» под слотами комплектов (подсказка по наведению) и обычный
инвентарь игрока. Числа считает сервер (по его конфигу) и присылает клиенту.

## Модификации

Значения при настройках по умолчанию (`magazineSize = 30`, `reloadTicks = 45`, `fireIntervalTicks = 3`, `spreadDegrees = 1.6`).

| Комплект | Эффект | Было → стало |
|----------|--------|--------------|
| Увеличенный магазин | +50 % вместимости магазина | 30 → 45 патронов (заряженные патроны **не сбрасываются**) |
| Улучшенный механизм перезарядки | −20 % времени перезарядки | 45 → 36 тиков (2.25 → 1.80 с) |
| Стабилизатор | −20 % разброса | 1.6° → 1.28° |
| Усиленный ствол | −10 % разброса (**урон не меняется**) | 1.6° → 1.44° |
| Улучшенная пружина | +10 % скорострельности | интервал 3 → 2.727 тика (400 → 440 в/мин) |

Правила: каждый вид ставится на автомат **один раз**; других бонусов нет; урон пули не трогается; стабилизатор и
ствол вместе дают ×0.8 × 0.9 = ×0.72 (−28 % разброса) — это максимум, больше ничто не суммируется. Если в конфиге
`fireIntervalTicks = 1`, автомат и так стреляет каждый тик, и пружина ничего не добавит (быстрее одного выстрела за тик
игра не умеет).

Скорострельность с дробным интервалом: выстрелы идут на тиках `floor(k · интервал)` (0, 2, 5, 8, 10, 13 …), то есть
через 2–3 тика со средним 2.727; при целом интервале это ровно прежнее `тик % интервал == 0`.

## Хранение (NBT автомата)

```
{ Ammo: 17, AkMods: ["magazine", "spring"] }
```
`AkMods` — список строк-id в фиксированном порядке. При чтении дубли и неизвестные id игнорируются (повреждённый тег не
даёт удвоенного бонуса и не роняет игру). `Ammo` и `ReloadEnd` установка не трогает, кроме одного: идущая перезарядка
отменяется (автомат лежал в верстаке, а не в руках), патроны остаются.

Всё вычисляется на сервере в `item/AkMods.java`; `AkRifleItem` и `AkClientExtensions` берут размер магазина, время
перезарядки, разброс и интервал выстрелов **только** через `AkMods`. NBT автомата синхронизируется обычным образом
(поэтому подсказка и анимация перезарядки на клиенте видят модификации).

Верстак хранит содержимое в самом блоке (как сундук): закрытие окна, выход из игры, перезапуск ничего не теряют;
при разрушении блока всё выпадает. Курсорный предмет при закрытии окна возвращается игроку обычной логикой Minecraft.
Смерть, передача и выбрасывание автомата — модификации лежат в его NBT и едут вместе с ним.

## Откуда брать комплекты

* **Крафт** (все рецепты бесформенные; запчасти, угольные пластины, ржавые шестерни и магазины в основном из лута):

| Комплект | Ингредиенты |
|----------|-------------|
| Увеличенный магазин | магазин для автомата, оружейные запчасти, железный слиток ×2 |
| Улучшенный механизм | оружейные запчасти ×2, редстоун ×2, ржавая шестерня |
| Стабилизатор | стальная балка, оружейные запчасти, редстоун, железный слиток |
| Усиленный ствол | угольная пластина ×2, стальная балка, оружейные запчасти |
| Улучшенная пружина | железный слиток ×2, редстоун, кокс, оружейные запчасти |

* **Лут сундуков** — отдельный пул (1 бросок, в основном пустой), чтобы не вытеснять остальное. Вес вида: ствол 4,
  пружина 4, стабилизатор 3, механизм 2, магазин 1 — чем полезнее, тем реже.

| Таблица | Шанс, что в сундуке будет какой-либо комплект | Какие виды |
|---------|----------------------------------------------|------------|
| `factory` (заводы) | 14/50 = 28 % | все пять |
| `blockpost_armory_north/south` (оружейные ящики блокпостов) | 14/40 = 35 % | все пять |
| `blockpost_supply` (ящики снабжения блокпостов) | 14/60 ≈ 23 % | все пять |
| `mine_deep` (глубокие шахты) | 13/60 ≈ 22 % | без магазина |
| `freight_station` (товарные станции) | 11/60 ≈ 18 % | ствол, пружина, стабилизатор |

Конкретный вид при выпадении: у магазина 1/14 ≈ 7 %, у механизма 2/14 ≈ 14 %, у ствола и пружины по 4/14 ≈ 29 %.
Порядок «реже = полезнее» проверяет `tools/validate.py`.

## Файлы

| Файл | Роль |
|------|------|
| `item/AkMods.java` | вид, константы эффектов, чтение/запись NBT, формулы, момент выстрела |
| `item/AkModItem.java` | предмет-комплект (подсказка; сам по себе ничего не делает) |
| `item/AkRifleItem.java`, `client/AkClientExtensions.java` | берут числа из `AkMods` (модель, поза, анимации не менялись) |
| `block/WeaponWorkbenchBlock.java`, `…BlockEntity.java` | блок (ПКМ открывает меню), хранилище на 6 слотов |
| `menu/WorkbenchMenu.java` | слоты, кнопка «Установить» (сервер), Shift-клик, статистика через `ContainerData` |
| `client/WorkbenchScreen.java` | окно в стиле ванили, нарисованное кодом (без текстуры окна) |
| `registry/ModBlockEntities.java`, `ModMenus.java` | регистрации |
| `gametest/AkModsGameTests.java` | формулы, «один раз на вид», патроны, меню, сохранение (не запускались) |
| `tools/content.py`, `gen_textures_mods.py`, `gen_worldgen.py`, `validate.py` | содержимое, текстуры, лут, проверки |

## Что проверять в игре первым делом

1. Блок виден (не «невидимый»), ПКМ открывает окно, оно не вылезает за экран при GUI-масштабе 3–4.
2. АК/комплекты кладутся только в свои слоты; Shift-клик работает в обе стороны; кнопка активна только когда есть что ставить.
3. После установки: комплект исчез, плашка зелёная, АК в руках — вместимость/перезарядка/разброс/темп изменились,
   патроны в магазине те же.
4. Выйти из игры с автоматом/комплектами в верстаке, зайти — всё на месте. Сломать верстак — всё выпало.
5. Мультиплеер: два игрока у одного верстака, смерть игрока с модифицированным АК, передача АК.
