# Ориентация автомата АК в руках (0.2.1)

## Что было не так в 0.2.0
Автомат был плоским спрайтом (`item/generated`) с трансформами арбалета: `rotation [-90, 0, -60]`.
Арбалетная трансформация сначала поворачивает спрайт вокруг X на −90°, то есть **кладёт плоскость спрайта горизонтально**
(для арбалета, нарисованного «сверху», это правильно). У автомата спрайт нарисован сбоку (ствол вправо, магазин вниз),
поэтому в руках он лежал на боку: магазин смотрел вбок, а в первом лице плоский спрайт, развёрнутый ребром к камере,
почти не виден. Знак отдачи в первом лице тоже был подобран под лежачий спрайт (дульный срез уходил вниз).

## Что сделано в 0.2.1
Автомат — настоящая 3D-модель из кубоидов (`tools/rifle_model.py` → `models/item/ak_rifle.json`, 18 элементов,
текстура-палитра `item/ak_rifle_model.png`). Ориентация модели: **ствол к −z, приклад к +z, магазин вниз (−y),
прицельные приспособления вверх (+y), окно выброса и затворная рукоять на +x** (правая сторона оружия).

Почему это даёт правильное положение без поворотов в руке:

* **Первое лицо.** Система координат предмета = система камеры: x вправо, y вверх, взгляд вдоль −z.
  Смещение руки `translate(±0.56, −0.52, −0.72)` (его же делает `AkClientExtensions.applyForgeHandTransform`) не вращает.
  Ствол (−z) идёт «от игрока вперёд», приклад (+z) у камеры.
* **Третье лицо, поза `CROSSBOW_HOLD` (обе руки подняты вперёд).** Цепочка `ItemInHandLayer`:
  поворот руки `Rz·Ry·Rx` (xRot ≈ −90°) → `Rx(−90°)` → `Ry(180°)` → смещение. Для поднятой руки
  `Rx(−90°)·Rx(−90°)·Ry(180°) = Rz(180°)`, то есть оси предмета: x → вправо, y → вверх, z → назад — как в первом лице.
  Поэтому тут тоже поворот не нужен; добавлен только `rotation [0, −15, 0]`: поза арбалета разворачивает правую руку на
  −0,3 рад (≈17°) к центру, и поворот на 15° выравнивает ствол по взгляду. Для левой руки `ItemTransform.apply`
  сам зеркалит знак поворота и смещения по x.
* **Проверка порядка осей.** `ItemTransform` применяет `Quaternionf.rotationXYZ` = матрица `Rx·Ry·Rz`
  (сначала Z, потом Y, потом X). Проверено на ванильном мече (`[0, −90, 55]`): остриё идёт вперёд и чуть вниз
  при опущенной руке — как в игре; для арбалета `[−90, 0, −60]` получается горизонтальный спрайт, направленный вперёд.
* **GUI / хотбар.** `rotation [0, −90, 0]`: поворот Y на −90° переводит −z в +x, то есть ствол вправо,
  магазин вниз — как у обычной иконки. Смещение рассчитано по габаритам модели, чтобы автомат был по центру слота;
  `gui_light: front` — плоское освещение, как у спрайтов.
* **Рамка.** Зритель стоит со стороны −z, поэтому тот же вид сбоку — `rotation [0, +90, 0]`.
* **Земля.** Предмет вращается вокруг Y сам; поворот не нужен, только масштаб 0,55.
* **Отдача.** В первом лице камера смотрит вдоль −z, дульный срез — это точка с z < 0. Положительный поворот вокруг X
  поднимает точки с z < 0 вверх (`y' = y·cos − z·sin`), поэтому отдача — `+recoil·3.5°` (в 0.2.0 было `−`: дульный срез
  уходил вниз).

## Расчётный просмотр
`python3 tools/preview_ak.py out.png` (нужны numpy и Pillow; к сборке не относится) прогоняет **настоящий** `ak_rifle.json`
через ту же цепочку матриц и рисует: первое лицо (правая/левая рука, перезарядка, отдача), третье лицо (справа, сверху,
сзади, спереди; правша и левша; взгляд вверх/вниз), GUI, рамку, землю. Картинка `docs/ak_preview.png` — результат.

**Это не скриншот игры.** Это моя реализация цепочки рендеринга по знанию кода Minecraft 1.20.1; если реальная игра
отличается от модели (например, иная поза рук), картинка может не совпасть. Проверка в игре не выполнялась.

## Защита от регрессии
`tools/validate.py → check_rifle_model` падает, если: у модели нет `elements` или родитель `item/generated`/`handheld`;
поворот в руках по X/Z не нулевой или yaw больше 20°; порядок «дуло → ствольная коробка → приклад» по z или
«магазин → коробка → прицел» по y нарушен; текстуры/UV/углы элементов недопустимы.
